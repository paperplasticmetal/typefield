# Typefield app and website releases

Every completed app fix or feature includes the matching public beta download. The app CI also checks that the website version, links and downloadable DMG checksum match both app plists. A source push alone does not finish a release. Documentation-only changes do not require rebuilding an unchanged app.

1. Preserve user fonts, saved Library/Spaces/Letterform data and unrelated work. Record saved-data hashes before installation.
2. Bump `Resources/Info.plist` and `Resources/Info-Store.plist` together. Update `CHANGELOG.md`, `docs/STATUS.md` and focused QA notes.
3. Run relevant native checks and `node tests/figma-import.test.js`. For window changes, run `dist/Typefield.app/Contents/MacOS/Typefield --window-self-test` in a GUI session and use `--window-qa` for disposable live projects.
4. Run `./install-local.sh` to build/test/install the single canonical `/Applications/Typefield.app`. Verify its version, strict signature, binary equality with `dist/Typefield.app`, and unchanged user-data hashes.
5. Run `bash package-beta-dmg.sh`. Verify the image with `hdiutil verify`, mount read-only, and compare the enclosed app version, signature and executable hash. Keep build artifacts out of app source control except the verified versioned public DMG under `marketing/website/dist/assets/`, which the existing website deploys.
6. Generate the signed update feed from the verified DMG with `python3 scripts/updater/generate-appcast.py --app dist/Typefield.app --dmg dist/Typefield-VERSION-beta.dmg --output marketing/website/dist/updates/appcast.xml --previous-feed marketing/website/dist/updates/appcast.xml` (omit `--previous-feed` only for the first updater release). The dedicated `typefield-updates` Keychain account must match `SUPublicEDKey`. Never export the private key into the repository. The generator verifies the mounted app, signs the immutable GitHub asset and final feed, and rejects non-increasing builds. Keep the feed on the default channel so published betas are offered; do not add branch builds or unreleased work.
7. Commit the verified source and notes, and push to `origin`. Create a versioned prerelease in the **public** `paperplasticmetal/typefield` repository, upload `Typefield-VERSION-beta.dmg` and its SHA-256 file, and verify the release asset. Use a new `vVERSION-beta.1` tag and never replace a previously published immutable DMG.
8. Reconcile the latest canonical website source from GitHub before editing. The public site is **https://typefield.app/** on Cloudflare Pages project `typefield`; the Sites project in `.openai/hosting.json` is a separate draft and is not the public download site. Preserve the current site design, feedback Function and D1/Turnstile bindings. Update the download page's version/build, same-origin DMG, exact GitHub release asset link, checksum and `_headers`, and publish the matching signed `updates/appcast.xml` in the same website deployment. Serve the feed with `Content-Type: application/rss+xml` and `Cache-Control: no-cache`; never edit the feed after signing. Keep release history in GitHub Releases and retain immutable assets. The user removed release history from the website download page; do not restore that section during a release update.
9. Run `python3 scripts/check-beta-website.py`, website JavaScript syntax checks and `npm test` in `marketing/website`. Commit and push the website changes. Deploy with the authenticated Wrangler CLI from `marketing/website`: `wrangler pages deploy dist --project-name typefield --branch main`. This includes `functions/`; dashboard-only static uploads omit the feedback API. Verify successful deployment, the live download page, feedback API, signed feed bytes, and identical unauthenticated GitHub and website DMG checksums. Fetch the public feed and DMG and run `scripts/updater/validate-appcast.py` against the public bytes. Verify that app → Check for Updates reports the expected release. Report any blocked publication explicitly.


Current beta requirements: Apple silicon, macOS 13 or later. The app is ad hoc signed, without Developer ID notarization. Keep the download instructions honest about macOS first-open approval until signing changes.

The updater is embedded only in the direct-download build (`build.sh`). The sandboxed Xcode/App Store target and plain Swift Package builds do not include Sparkle or use the direct update feed. Existing users of builds before this updater must manually download an updater-enabled version once. Future completed releases must include a signed appcast; the website check fails if it is absent, stale, tampered, or points to a different app build.

Before publishing, fetch and integrate the latest canonical app and website commits. Never install or publish a stale feature-branch snapshot over a newer released app. Coordinate one release at a time; rebuild after integration and choose a version/build greater than every published version. Keep existing users’ library/project data and all other agents’ unfinished files intact.
