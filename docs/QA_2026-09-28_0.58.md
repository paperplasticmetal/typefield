# Typefield 0.58 width refinement

The 85% target is not met. The native generator now combines procedural editable outlines with a small learned width prior. Shape IoU is not calibrated confidence.

## Retained change

For proportional projects with complete H O n o p references, a local linear model estimates the missing letters' ink widths. It uses eight dimensionless measurements and 47 sets of nine coefficients, trained from 1,036 explicitly OFL-metadata faces in 289 families. Benchmark lineages were excluded; deterministic family-level validation selected regularization before a frozen full-corpus refit. No font outlines, remote service, Python runtime or external checkpoint are bundled. Numeric-only export and reproduction tools are included under `scripts/starter-research/`.

Predicted widths describe complete ink bounds. Applying stem-row insets again would incorrectly shrink letters with overhanging terminals; the implementation instead preserves actual source padding in the side bearing. Monospaced projects, missing references, extreme feature values, excessive bearings and invalid output geometry retain the earlier construction. Constructed suggestions remain explicitly provisional. Source contour reuse takes priority over the width prior.

## Measurements

All native audits use five references and the same fixed physical coordinate frame, with every withheld letter counted. The original 92 × 72 development score increases **52.9% → 53.6%**; the 368 × 288 result is also **53.6%**. The additional nine increase **47.3% → 48.3%**. Ten further faces, chosen before scoring the frozen width prototype, increase **48.5% → 50.4%**. Those faces are now observed, and none of their family names is in the width-training cohort. Related designs across families remain a limitation.

Examples of gains: Avenir 56.8% → 61.9%, Noteworthy 38.1% → 40.2%, Baskerville 44.1% → 47.7%, Didot 39.9% → 44.3%, Futura 64.5% → 68.4%. Regressions are retained in the report: Helvetica 66.7% → 64.6%, Times 54.4% → 53.4%, Comic Sans 50.9% → 49.7%. The two monospaced development fonts and several out-of-domain scripts remain unchanged. These results do not justify a production-quality missing-letter claim.

Editable curve construction is preserved. Textured source outlines can still be complex: the new Chalkduster audit includes a reused suggestion with 711 anchors. That is a source-texture limitation, not a claim that every generated outline is compact. No automatic loss of those details was introduced to improve anchor counts.

## Reproduction

Use `--starter-quality-audit` with `--starter-validation-set`, `--starter-challenge-set`, or neither. The two set flags are mutually exclusive. `--starter-grid-scale 4` checks the finer grid. `--starter-disable-width-prior` restores the 0.57 construction; `--starter-disable-stem-reuse` separately disables the earlier cap-stem work. Reports and font fixtures remain private in `.context/` or temporary directories.


## Separate learned-vector research

A locally trained model was extended with cursive/handwriting fixtures, family-balanced sampling and reference-only latent refinement. A raster coverage mismatch was found and corrected before drawing a native-quality conclusion. Its final **native editable-vector** result is **62.2% original / 58.7% additional**, compared with its corrected raster result of 62.3% / 58.8%. All 846 candidates passed glyph validation and TrueType export; mean editing anchors were 35.7, maximum 354. A blanket source/model hybrid regressed to 61.2% / 57.4% and was rejected. These are research-only outputs; the app continues to use the tested 0.58 generator. Full protocol and limitations are in [the research notes](../scripts/starter-research/README.md#native-vector-check-and-raster-correction).

The 85% objective remains open. None of the silhouette scores is a calibrated confidence estimate. The alternative DeepVecFont-v2 checkpoint download failed before inference; that model has no reported result.
